# DevImpact – 90-Day Sample Engineer Activity (Narrative Outline)

This document describes a realistic 90-day slice of work for a mid–senior product engineer on a cross-functional team.
It is used as the canonical reference for seed data and demos.

⸻

## Engineer Profile

    •	Role: Senior Software Engineer (Product-focused)
    •	Team: Web Platform / Product Infrastructure
    •	Repos:
    •	acme/web (frontend + some shared logic)
    •	acme/api (backend services)

⸻

## High-Level Themes (Threads That Should Emerge)

    1.	Feature Project A – Activity & Threading Foundations
    2.	Feature Project B – Performance & Data Model Improvements
    3.	Feature Project C – UX Improvements & Edge Case Handling
    4.	On-Call / Incident Response Week
    5.	Tech Debt & Refactors
    6.	Collaboration & Code Reviews Across Team
    7.	Alignment & Meetings (Planning, Design, Demos)
    8.	Hiring & Interview Support

⸻

## Timeline Overview (90 Days)

### Weeks 1–4: Feature Project A (Core Product Work)

Theme: Building foundational infrastructure (high cognitive load, fewer but larger PRs)
• Kickoff design discussion with product + backend
• Architecture review meeting (1 hr)
• Several medium-to-large PRs:
• Data model changes
• Activity normalization logic
• Indexing & query optimizations
• Multiple review rounds on key PRs
• Demo to product/design stakeholders
• Follow-up cleanup PRs

Meetings
• Design review (architecture)
• Demo (non-recurring)
• Regular standups
• Sprint planning + retro

⸻

### Weeks 5–7: Feature Project B (Performance & Reliability)

Theme: Iterative improvement, more frequent PRs
• Identify performance bottlenecks
• Break work into smaller incremental PRs
• Add metrics/logging
• Refactor hot paths
• Collaboration-heavy:
• Reviewing teammates’ PRs
• Being requested as a reviewer for tricky changes

Meetings
• Design review (shorter, more tactical)
• Cross-team sync (org-level)
• Sprint ceremonies continue

⸻

### Week 8: On-Call Rotation (High Noise, High Signal)

Theme: Context switching, urgency, reactive work
• On-call for one full week
• Incident triggered by production issue
• Activities include:
• Incident response meeting (off-hours)
• Hotfix PRs (small but urgent)
• Follow-up PRs for robustness
• Incident retro meeting
• Increased meeting load
• Fewer feature PRs

Meetings
• Incident response (1–2 ad hoc)
• Incident retro
• Org update / postmortem readout

⸻

### Weeks 9–10: Feature Project C (UX + Edge Cases)

Theme: Polishing, product-facing improvements
• Smaller PRs focused on:
• UX fixes
• Edge cases
• Bug fixes surfaced by users
• Coordination with design & QA
• Demo to product stakeholders

Meetings
• Demo
• Design review (lightweight)
• Sprint planning + retro

⸻

### Weeks 11–12: Tech Debt, Cleanup, Transition

Theme: Pay down debt, unblock others, prepare next phase
• Refactor legacy code touched earlier
• Rename / reorganize files
• Improve test coverage
• Close lingering review comments
• Help teammates unblock work

Meetings
• Architecture discussion (optional)
• Org/company meeting
• End-of-quarter planning

⸻

## Ongoing Work Throughout All 90 Days

Code Reviews & Collaboration
• Regularly reviewing PRs from:
• Teammates on same team
• Adjacent teams
• Types of reviews:
• Simple approvals
• Comment-heavy feedback
• Blocking reviews
• First responder reviews
• Some reviews not directly related to main feature projects

⸻

## Recurring Meetings (Baseline Load)

• Daily standups: Monday–Thursday (15 min)
• 1:1 with manager: Every 2 weeks (30 min)
• Peer 1:1: Every 2 weeks (30 min)
• Sprint planning: Every 2 weeks (1 hr)
• Sprint retro: Every 2 weeks (45 min)

These are assumed, low-signal individually, but shape available focus time.

⸻

## Hiring & Interview Support

• Participate in interview loops:
• 1–2 phone screens
• 1 onsite / virtual onsite
• Activities include:
• Reviewing candidate resumes
• Interview meetings
• Providing written feedback
• Scattered across last 30–45 days

⸻

## Org / Company Context

• Company-wide all-hands (monthly)
• Occasional org-level sync
• Some meetings attended but not central to day-to-day work
